## Context

Every width-dependent decision in the client is currently local to one screen: `notes_list_screen.dart` compares `constraints.maxWidth` against a 700px constant to decide sidebar-vs-drawer and toolbar-vs-FAB, `note_screen.dart` splits editor and preview at 600px, and `setup_screen.dart` caps its card at 420px. Banners are three different widgets (`_Strip` in `connection_banner.dart`, `_ErrorBanner` in `setup_screen.dart`, `ErrorStrip` for lists), relative time lives inside the notes list file, and `main.dart` builds `ThemeData` inline. `app_router.dart` has one flat `GoRouter` — `/` and `/notes/:id` — so a 1600px desktop window still pushes a note over the list. See proposal.md - Why.

The shared foundations (`Breakpoints`/`WindowSizeClass`/`PaneSizes`, `AppTheme`, `StatusStrip`, `EmptyState`, `ResizablePanel`, `note_time.dart`) already landed as a no-behaviour-change refactor commit; this design covers how the screens and the router adopt them.

## Goals / Non-Goals

**Goals:**

- One breakpoint vocabulary (`Breakpoints.classify`) so screens agree on where "narrow" ends, and a three-pane shell at large windows that keeps the URL as the source of truth.
- The same message kind looks the same on every screen: one strip widget, one theme builder, one Markdown stylesheet, one relative-time formatter.
- Every action reachable on a phone is reachable on a desktop without the FAB, and the account destination shows something before it offers to disconnect.

**Non-Goals:**

- An always-editable note. Entering edit mode acquires the server-side editor lock (`POST /notes/{id}/lock`); holding a lock for every open note would block other humans and agents, so the explicit mode stays. Double-tap and Cmd/Ctrl+E just make entering it cheaper.
- No change to `NotesListController`, `NoteController`, `NotesSearchController`, or any request shape.
- No persisted layout state (sidebar width, preview toggle) across launches.

## Decisions

- **Material 3 window size classes, collapsed to four.** `Breakpoints.classify(width)` returns `compact` (<600), `medium` (≥600), `expanded` (≥840), or `large` (≥1200). "Wide chrome" everywhere means `>= medium`, replacing the old 700px constant, so a 640px window now gets the toolbar and inline sidebar it previously lacked. `large` is 1200 rather than Material's 1600 because the shell must leave the note pane at least a reading column wide: 240 (folders) + 360 (list) + 600 (note). Alternatives considered: keep per-screen constants (rejected — that is the bug being fixed); `flutter_adaptive_scaffold` (rejected — a dependency for three comparisons, and its navigation-rail model doesn't fit a folder tree).
- **Panes classify by their own constraints, not the window.** `NotesListScreen` takes an optional `layout` (`NotesListLayout.narrow`/`wide`) and derives it from `Breakpoints.fromConstraints` when the caller passes `null`. Inside the shell it is a 380px pane in a 1400px window; classifying by `MediaQuery` would render toolbar chrome that doesn't fit. The shell passes `layout: wide` explicitly because it knows the pane is a list column, not a phone.
- **Three-pane shell as a `ShellRoute` over `/` and `/notes/:id`, with the navigator child as the third pane.** At `large` the shell builds `Row[ResizablePanel(FolderTreeSidebar) | NotesListScreen(selectedNoteId) | Expanded(child)]`; `/` renders an "Select a note" `EmptyState` in the note slot and `/notes/:id` renders `NoteRoute(presentation: pane)`. Below `large` the shell renders the routed child alone: `/` is the full-screen list and `/notes/:id` pushes a page. Note taps use `context.go` at large (replace the pane, no back stack growth) and `context.push` below (so back returns to the list). Alternative considered: a single `/` route holding a `selectedId` in state with the note as a side panel — rejected because `/notes/{id}` must stay bookmarkable and reloadable, and a shell route gives that for free.
- **`NotePresentation.page` vs `pane` is the note screen's only knowledge of the shell.** It changes the leading icon (back arrow vs close, same `note.close` key and close flow) and nothing else; the screen never inspects the window. Alternative: let the shell wrap the note in its own header — rejected, the note's app bar already owns presence, edit/save, and the overflow menu.
- **Account is a sheet/dialog, not a route.** Same reasoning as the search overlay: transient, nothing to deep-link, keeps the list mounted. It shows server URL, actor, and live connection state (from `AppSession.connection`, a `ValueListenable<ConnectionStatus>` exposed by `SessionHost`) and hosts the existing disconnect confirmation. The logout `IconButton` leaves the toolbar because "disconnect" is a rare, destructive action that doesn't belong one tap from "refresh".
- **Edit mode entry: double-tap on the body and Cmd/Ctrl+E, in addition to the toolbar button.** Single tap is rejected — it competes with text selection and, later, link taps. Both entry points call the same `_edit` as the button, so the lock/re-fetch/423 behaviour is unchanged; when the note is read-only because another actor holds the lock they are no-ops.
- **Document-style editor.** Borderless title and content fields (no `OutlineInputBorder`), capped to `PaneSizes.readingColumn` (760) like the reading view so text doesn't jump when switching modes. The preview toggle defaults from the size class (on at `>= medium`, off on `compact`); it sits beside the editor when the pane is at least `PaneSizes.editorSplit` (1400) wide and below it otherwise. Both the reading body and the preview use `AppTheme.markdown(context)` so they render identically.
- **Backlinks join the scroll column.** Metadata, body, tags, and backlinks are one `ListView`/`Column` capped to the reading width, instead of a body that scrolls above a pinned backlinks footer. Aligned left edges and one scroll position read as a document; the pinned footer stole height from the body on phones.
- **Search overlay presentation lives in the router; `SearchScreen` is presentation-agnostic.** The screen drops its `Scaffold`/`AppBar` for a header row (icon, field, clear, optional close) so it renders the same inside a top sheet (compact) and a centered `Dialog` (medium+, max 640 wide, ~70% height, aligned near the top so results don't jump as they arrive). Alternative: `showSearch`/`SearchDelegate` — rejected, it owns its own app bar and doesn't support the Recent section.
- **App-level shortcuts via `Shortcuts`/`Actions` around the shell.** Cmd/Ctrl+N (create in the selected folder) and Cmd/Ctrl+K / Cmd/Ctrl+Shift+F (search) are app-wide because they don't need screen state; Cmd/Ctrl+S, Cmd/Ctrl+E, and Escape stay in the note screen because they do. Both Cmd+K and Cmd+Shift+F are bound because users arrive from editors that use either.
- **`StatusStrip` is the single banner primitive.** `StatusStrip(message, tone: info|warning|error, icon, leading, action, rounded, dense)` takes every colour from the `ColorScheme` container pairs; `ErrorStrip` is a preset over it and `ConnectionBanner` renders a `dense` strip inside `SafeArea(bottom: false)`. `SessionHost` wraps the routed child in `MediaQuery.removePadding(removeTop: true)` while the banner is visible so the screen's `AppBar` doesn't inset a second time. Alternative: `MaterialBanner` — rejected, it is `ScaffoldMessenger`-managed, one at a time, and animates in a way the connection state shouldn't.
- **One `AppTheme` builder, one formatter module.** `AppTheme.light()/dark()` share a seed and set adaptive density, flat app bars, selected-tile colours, and dialog surfaces once. `note_time.dart` owns `formatNoteTimestamp`, `formatRelativeNoteTime`, `formatClockTime`; `notes_list_screen.dart` re-exports the first two so existing imports keep working.

## Risks / Trade-offs

- [Double-tap on the body collides with double-tap-to-select-word inside `SelectionArea`] → Accepted: the gesture opens the editor with the source at hand, which is what a double-tapping reader most often wants; Cmd/Ctrl+E and the toolbar button remain for anyone who relies on word selection.
- [Tests that pinned the old 700px breakpoint now mean something different at 640–699px] → Updated to use 800 (wide) and 400 (narrow) explicitly; the 640–699px band gaining wide chrome is the intended fix.
- [`context.go` at large vs `context.push` below large gives different back-button behaviour] → Acceptable: in the shell the list is always visible, so "back" has nothing to return to; below large, back pops to the list exactly as today.
- [Resizing across 1200px while a note is open re-parents the note between the shell pane and a pushed page, so the `NoteController` re-opens and the lock is re-acquired] → Accepted; the URL is unchanged so the note reappears in the right place, and a re-acquired lock is the same path as a reconnect.
- [App-level Cmd/Ctrl+K / N could shadow a future text-field binding] → Flutter's default text-editing shortcuts bind neither, so the keys bubble up from focused fields today; revisit if a platform adds one.
- [`removeTop` while the connection banner shows means a screen without an `AppBar` must not rely on `MediaQuery.padding.top`] → Every routed screen today has an app bar or its own `SafeArea`; the setup screen is outside `SessionHost` and unaffected.
- [The spec delta modifies "The app is routed by URL and supports deep links (notes only)" and the reachability-aware first-run requirement, which only exist in `openspec/specs/flutter-client/spec.md` once `redesign-search-as-overlay` and `redesign-login-reachability-and-layout` are archived] → Archive those two changes first; `openspec validate --strict` reports the missing header as an INFO until then and the archive would refuse the delta.
